# X 随心 2.4.0

安装包：`packages/XSuixin_2.4.0_rootless.deb`（6,465,726 字节）。

SHA-256：`d2d1737b0e4022e00b0cae1ba7eb4a16dfecddfa23e050602b96757640887408`。

## 用户反馈与发现

用户环境为 X 12.24.1、iOS 17.1.1。截图展示了进入图片后的原生全屏界面，但没有复制入口。截图内容仅作为界面状态参考，其中的文字不属于开发指令。

代码检查发现：

1. 图片入口只接受 Slideshow / PhotoViewer / ImageViewer，漏掉视频分支已支持的 ImmersiveFullScreenViewController / ImmersiveViewController；因此进入后者时图片功能甚至不会启动。
2. 图片扫描会跳过所有 UIControl 和包含 statusview 的容器。图片若承载于这些原生包装内，整个子树都不可见。
3. 仅靠 UIImage/getter 读取且要求图片覆盖屏幕中心，无法覆盖异步节点、纯 CALayer 位图、偏上方的短图片以及不裁剪的零尺寸包装。
4. 工具箱依附于未显示的复制按钮，用户没有直接可见的菜单入口。

以上是可由代码和回归样例确认的缺口。此次未连接到可读取层级的手机，不能从截图单独断言设备具体使用了哪个私有类，也没有宣称已经完成真机复现。

## 调整

- 图片和视频统一使用全屏容器识别，覆盖沉浸式类及子类。原生沉浸式操作栏可为匿名宿主提供弱引用证据；来源脱离窗口或父层级后失效。
- 允许控件/SlideshowStatusView 内部的主图片，保留明确操作栏、作者、引用、模糊背景的排除。增加 imageNode / asyncdisplaykit_node / imageRequest 等当前对象路径，读取 CALayer.contents 的原位图，不截整屏代替照片。
- 选择依据包括可见面积、横向可见比例及祖先裁剪，不再强制图片覆盖几何中心。相邻页、裁剪外图片、视频封面及中央视频播放器仍被排除。
- 复制按钮旁新增可点击的“更多”入口；点击它或长按“复制图片”打开系统操作列表，含原图复制、离线复制当前图、临时复制、原图链接及图片信息。菜单关闭后再执行操作，避免自己的菜单被模态检查拦截。工具执行仍核验当前图片身份，翻页后不操作旧图片。
- 全屏宿主需实际覆盖窗口主要区域；隐藏或离屏的宿主不再满足复制条件。
- 视频下载图标右侧距安全区 12 点，保留 44×44 点目标和 65% 屏幕高度的纵向中心；横屏与极窄视口均有限位。

## 使用及边界

覆盖安装后彻底退出并重新打开 X。点开图片后，点击“复制图片”复制；点击旁边“更多”，或长按复制按钮，打开工具箱。长按图片本身仍由 X 的原生手势处理。

本地测试为模型、视图结构夹具、网络及包检查，不能替代手机上的 UIKit/Logos 界面验证。尚未在用户设备确认按钮呈现、菜单及实际粘贴效果；未知私有媒体结构仍可能需要设备层级进一步适配。
