# 2.4.7-5 实际运行验收与反馈流程

此构建增加了手机内的验收页面。本地自动检查与 arm64 编译不代替真实设备操作，以下项目仍由用户安装后验证。

1. 安装后彻底退出并重开 X，进入“X 随心 → 运行状态与恢复 → 实际运行验收”。确认完整构建为 2.4.7-5，点“开始一次新验收”。
2. 离开验收页，逐项实际操作。可先测图片权限与保存、隐藏转推详情及返回、三指恢复菜单，再测暂停与恢复后的两次重启。
3. 回看结果及失败阶段。系统完成回调只证明系统事务完成；保存的图片内容、方向、导出接收及实际流畅程度要人工核对，可点击项目记录“符合预期”或“存在问题”。
4. 测性能前点“开始性能观察”，连续浏览 X，回来停止或等待 20 分钟自动停测。后台暂停计时，至少 30 秒及 120 个回调间隔才表示有足够观察样本，不能自动判为通过。
5. 异常时点“导出报告与日志”，保存并发送附件，同时描述操作步骤、期望结果和实际现象。报告含构建身份、轮次、X/iOS 版本、失败阶段与错误码；日志默认脱敏，不自动上传。
6. 下一构建修订递增为 2.4.7-6，再从新轮次复验。新构建不沿用旧构建的通过结果；开始新一轮前先导出需要保留的旧报告。

页面中的“待验证”表示尚未触发、数据不足或证据不可读取；“已观察到成功”表示系统或页面提供了实际成功证据；“人工确认”明确来自用户核对。返回时目标行不可见不会当成隐藏失败。X 无法启动前的崩溃和插件真实耗电无法由该页面捕获，可补充系统崩溃报告和实际使用反馈。

验收时记录设备型号、iOS 与 X 版本、插件完整构建号、运行状态页的提交号。先确认相应功能启用且未暂停。
