# 2.5.0-2 实际运行验收与反馈流程

上一版2.5.0-1用户审计确认：全屏两个视频解析失败、首页添加仍可点击；单张离线当前图复制、单个分享PNG和短性能样本不足判据通过。报告不证明其余场景通过。本版没有真实设备验收结果，首先按 [2.5.0-2 发布记录](RELEASE-2.5.0-2.md) 复验F1/F2及S1—S5/S8；S6/S7/S9仍列后续。

本版汇总遗漏的日志隔离、验收页刷新、首页添加入口及操作栏下载修复，并加入图片复制验证、日志聚合和性能样本状态修正。正式仓库为 Caun1112/XSuixin。当前没有 2.5.0-2 的真实设备验收记录，本地检查与 CI 不代替设备操作。

此前在 X 12.24.1 / iOS 17.1.1 上确认安装了 2.4.7-6（来源提交 `7919d0c`），设置入口、运行状态、日志查看、脱敏保存与 USB 取回已通过。该旧构建同时复现了首页添加入口未隐藏、验收页周期性跳动和导出自身 JSON 造成队列反馈；这些结果不作为 2.5.0-1 的通过记录。未完成的功能仍保留待测。

1. 新包生成并安装后彻底退出并重开 X，进入“X 随心 → 运行状态与恢复 → 实际运行验收”。确认完整构建为 2.5.0-2，源码仓库为 Caun1112/XSuixin，点“开始一次新验收”。
2. 离开验收页，逐项实际操作。可先测图片权限与保存、隐藏转推详情及返回、三指恢复菜单，再测暂停与恢复后的两次重启。
3. 回看结果及失败阶段。系统完成回调只证明系统事务完成；保存的图片内容、方向、导出接收及实际流畅程度要人工核对，可点击项目记录“符合预期”或“存在问题”。
4. 测性能前点“开始性能观察”，连续浏览 X，回来停止或等待 20 分钟自动停测。后台暂停计时，至少 30 秒及 120 个回调间隔才表示有足够观察样本，不能自动判为通过。
5. 异常时点“导出报告与日志”，保存并发送附件，同时描述操作步骤、期望结果和实际现象。报告含构建身份、轮次、X/iOS 版本、失败阶段与错误码；日志默认脱敏，不自动上传。
6. 下一构建修订递增为 2.5.0-3，再从新轮次复验。新构建不沿用旧构建的通过结果；开始新一轮前先导出需要保留的旧报告。

页面中的“待验证”表示尚未触发、数据不足或证据不可读取；“已观察到成功”表示系统或页面提供了实际成功证据；“人工确认”明确来自用户核对。返回时目标行不可见不会当成隐藏失败。X 无法启动前的崩溃和插件真实耗电无法由该页面捕获，可补充系统崩溃报告和实际使用反馈。
