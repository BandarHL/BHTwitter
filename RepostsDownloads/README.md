# X 随心 2.4.7-5（Rootless，内置验收与诊断日志）

从 BHTwitter 工作区独立提取的插件，包含转推隐藏、视频和动图下载、推文底部元素及底部导航栏精简。

## 安装

以后仅生成一个 rootless 安装包，默认内置诊断日志。在“X 随心 → 文件与诊断 → 诊断日志”中查看、刷新和导出，无需安装另一种包。说明见 [诊断日志](AVATAR-DIAGNOSTICS.md)。

安装 `packages/XSuixin_2.4.7-5_rootless.deb`，可从 2.4.4～2.4.7-4 升级。完成后彻底退出并重开 X，已有设置保留。完整包版本包含修订号，后续修订依次为 2.4.7-6、2.4.7-7；不同源码不重复使用已发布构建号。

- 面向 iOS 15.0 及以上的标准 rootless 越狱环境，使用 `/var/jb` 前缀。
- 包架构为 `iphoneos-arm64`，动态库为 `arm64`。
- 通过 Sileo/Zebra 安装后，完全退出并重新打开 X/Twitter。
- 可直接覆盖升级本插件 1.0.0 / 1.1.0 / 1.2.0 / 1.3.0 / 1.4.0 / 1.5.0 / 1.6.0 / 1.6.1；保留已有开关，未保存过转推显示方式时默认选择「隐藏条」；1.3.0 新增的「隐藏首页添加＋」「全屏右下角独立下载按钮」默认开启。
- 与完整版 BHTwitter、Hide Reposts 独立插件声明冲突；请先卸载旧插件，避免重复 hook。
- 不是 roothide 包，也不是 TrollStore/侧载安装包，不需要 IPA。

## 当前：2.4.7-5 TAV 播放资源兼容

根据用户 X 12.24.1 / iOS 17.1.1 真机诊断，补齐 `TAVPlayer.internalState/mainThreadState → currentItem → tech → avPlayer` 与 `foundationItem → avPlayerItem` 的只读资源路径。`tech.qualityEndpoints` 的端点集合是仅含质量信息的 NSSet，不将其当作 URL；仅在当前项范围内，对已验证的 `TAVFoundationPlayerEndpointsManager` 读取对象 ivar `_manifestURL`。资源加载器使用自定义 scheme 时，不改写 URL，只有取得真实网络地址才交给下载器。

所有可见播放器候选先参与解析，不再遇到第一个无法读取的包装器就立即终止。相同播放项可合并，多个真实当前资源冲突仍拒绝。日志增加候选结果、解析阶段与有限对象路径，明确资源缺在哪一层。右侧独立图标和原生下载参数桥接保留；验证与边界见 [2.4.7-5 发布记录](RELEASE-2.4.7-5.md)。

## 2.4.7-4 恢复右侧悬浮下载入口（保留）

修复 2.4.7-3 只有读到可下载地址才显示按钮的回归。当前可见播放器、播放控件或原生当前视频媒体即可显示右侧纯图标入口，不依赖 URL 和清晰度。加载中及控制栏淡出仍保留；明确切换到图片、离开全屏、关闭功能或打开其他菜单时按状态隐藏。位置仍为屏幕高度 65%、右侧安全区内 12 点，触摸区域 44×44。

全屏直接读取当前原生操作栏的 `viewModel` / 自身适配器模型，以及当前 slideshow 的 `media`，复用帖子下载按钮的完整视频参数。播放器未公开 URL 时也可显示当前帖明确分组的多视频菜单；原生字段未加载时仅允许使用当前非零帖子 ID 对应的、已核对实体未复用的短期参数缓存。已确认播放地址与旧原生模型冲突时使用当前播放资源。邻页、引用、离屏和其他帖子的参数仍不能借用。

新增 `fullscreen_download_visibility` 基础日志，记录实际入口布局与显示状态。完整说明与验证见 [2.4.7-4 发布记录](RELEASE-2.4.7-4.md)。

## 2.4.7-3 全屏视频直接读取（历史）

针对全屏视频已经播放、却必须点评论加载帖子后才能下载的反馈，改为读取当前可见的播放器和播放资源包装。优先当前播放 MP4/HLS，与其资源身份匹配后才能补回原生清晰度列表；不再依赖评论详情加载。没有 PlayerLayer 的受支持播放器包装同样可解析。

移除跨卡片保留旧模型的兜底，排除隐藏、离屏与相邻视频。多资源冲突或无法确认当前视频时安全停止。点击下载绑定选中的播放项，滑动切换会取消旧重试；质量选择和 HLS 探测返回也重新核对，避免误下载其他视频。

验收页增加“全屏视频读取与菜单”，记录实际读取、失败原因和菜单呈现；菜单成功不代表传输完成。诊断会记录发现的播放器/模型计数与包装路径。检查与实际边界见 [2.4.7-3 发布记录](RELEASE-2.4.7-3.md)。

## 2.4.7-2 实际运行验收（保留）

进入“X 随心 → 运行状态与恢复 → 实际运行验收”，开始一次验收后回到 X 实际操作，再回来查看照片权限、保存阶段、三指恢复、暂停/恢复后重启和隐藏转推详情返回的结果。尚未操作的项目保留待验证；未知详情身份或返回时目标行不可见，也不会冒充通过或失败。已确认的错误页、保存失败等显示具体阶段与错误域/码。支持明确标注的人工核对。

性能观察需主动开始，离开验收页可连续浏览 X；仅记录前台显示回调间隔、进程内存及采样峰值、热状态和内存警告，20 分钟自动停止。样本充足只表示有观察数据，不代表性能通过，也不测真实视频帧率或耗电。

“导出报告与日志”生成本轮验收 JSON、性能 JSON 和脱敏日志附件，含完整构建和源码提交，供用户主动发送反馈。验收轮次跨重启保存，新构建重新验收，旧轮次异步回调不会混入新结果。系统分享完成只证明分享活动完成，接收端是否收到仍需核对。

本地回归和构建验证不替代手机验收。操作步骤见 [真机验收清单](DEVICE-ACCEPTANCE.md)，发布记录见 [2.4.7-2](RELEASE-2.4.7-2.md)。

## 2.4.7-1 稳定性、隐私与保存策略（保留）

- “运行状态与恢复”显示完整构建号、源码提交、X/iOS 版本、已安装或实际调用的能力及广告部分覆盖边界。可暂停全部功能、恢复默认；暂停后重启跳过功能 hook。原设置值保留并置灰。
- 设置入口失效时三指长按 1.5 秒打开恢复菜单。X 无法启动时，用 Filza 在 X 数据容器 `Library/Application Support/XSuixinSafety` 创建空的 `disabled` 文件，重启进入恢复状态；恢复后也需重启。该后备方案仍需用户设备验收。
- 默认基础日志，模型/视图详细反射默认关闭；可临时开启 10 分钟。支持清空、脱敏导出、丢弃/写入失败统计，清理超过 7 天的记录。只在本机采集，不自动上传。
- 保存菜单明确区分原图和当前显示图。原图失败先询问；成功以可见短提示显示来源及尺寸。相同图片在本进程中重复保存需确认，不读取相册查重。图片资源预算降低为 32 MP。
- 工具箱图片/链接复制默认仅本机，可选 10 分钟过期。临时复制固定仅本机 10 分钟。
- 下载保留规则为 7/30 天或不按时间清理；重要文件可单独永久保留，重命名后标记保留，成功导出也不删除其本机副本。普通文件成功单项导出仍删除副本。规则调整不立即清理，手动清理有确认。

本地检查不代表真实手机已经验收。固定步骤与当前待验项目见 [真机验收清单](DEVICE-ACCEPTANCE.md)。版本出处和验证结果见 `RELEASE-2.4.7-1.md`。

## 2.4.3 原生头像延迟到达时的回退

真机日志显示作者身份正确、头像 URL 为空，但 `TUIAvatarImageView` 稍后有图。2.4.3 增加无 URL 时的原生头像回退：读取视图自身的 `user` / `userViewModel.user` 核对原作者，再检查图片是否为本次绑定后到达或已有同一账号的赋图记录。仅凭头像位置、用户名标签或修改后的用户绑定不会采用旧位图。

支持 UIImage 和 CALayer.contents 图片，在进入列表后的 0.15、0.6、1.5、2.5、4、7、12 秒检查，并响应原生 setImage 更新。每次检查重新核对当前行、原帖 ID 和作者，排除引用/媒体区域及离屏回收的零尺寸视图。模型也补充 `profileImageMediaEntity.mediaURL` 等头像资源读取。

新增 14 项回归检查覆盖 URL 资源、延迟位图、返回恢复、复用旧图、ID 冲突、未知身份及仅 layer.contents 有图。2.4.3 的真机显示效果仍需安装复验；若仍占位，诊断日志会明确记录原生头像身份是否匹配、是否有新图片及是否完成赋图。发布核验见 `RELEASE-2.4.3.md`。

## 2.4.2 原作者头像补全

针对昵称、用户名已显示但头像仍为占位图的反馈，补全同一原作者资料之间的头像合并、原生头像请求包装及旧式头像 URL 读取。仅在用户 ID 或用户名匹配时补齐资料；数字 ID 冲突时拒绝合并。分开返回的用户资料也可通过用户名与尚无 ID 的展示作者关联。

头像请求支持缺少图片 MIME 或使用二进制 MIME 的可解码图片，失败后在当前可见行自动重试两次。复用、作者变更和新请求都会阻止过期响应及重试更新当前头像。继续禁止从附近原生 UIImageView 借用未确认身份的像素。

新增 26 项回归检查，覆盖资料拆分、延迟返回、身份冲突、URL 限制及自动重试。安装后完全退出并重开 X，再刷新时间线。本版尚未在用户的 X 12.24.1 / iOS 17.1.1 手机上验证；截图不能确定设备上具体缺失的字段。发布核验见 `RELEASE-2.4.2.md`。

## 2.4.1 转推预览身份与返回恢复

修复转推缩略图中的昵称、@用户名和头像可能属于不同账号，以及详情返回后退回“转推作者”占位的问题。

- 补齐原生 `representedFromUser` / `representedFromUserID` 与原帖 `fromUser` 路径，明确区分展示的原作者和外层转推者。原帖明确关系优先；姓名、用户名、头像作为同一身份合并，部分字段不足时不借用转推者资料。
- 缩略图不再从正在复用的原生姓名标签或 UIImageView 取值；使用绑定模型的作者资料和头像 URL，避免“标签已经更新、头像还没更新”的瞬时混配。
- 已确认的原作者元数据按原帖/转推 ID 缓存，并保存在对应模型快照中。视图销毁、模型重建、详情返回或空字段更新不会清空已知资料；零 ID 不再让多条帖子共享同一个缓存键。
- 返回时间线时重新配置当前可见行；请求失败的头像可重新获取。旧请求只有在单元格状态和请求标记仍匹配时才能更新头像与图片缓存。
- 新增 25 项身份/模型生命周期检查、23 项直接调用生产预览配置与恢复函数的检查，均加入 `tests/run_all.sh`。视图和网络在这些检查中由可控夹具提供，不代表真机运行已验证。

模型与缓存都没有原作者资料时保留占位，不拼接其他账号。此缓存为进程内缓存，重启后由 X 的数据重新建立。安装后请彻底退出并重新打开 X，刷新“正在关注”/“为你推荐”；本版尚未在用户手机验证。

发布核验见 `RELEASE-2.4.1.md`。

## 2.4.0 全屏图片入口兼容修复

针对用户在 X 12.24.1 / iOS 17.1.1 图片全屏页面看不到复制入口的反馈：

- 视频下载图标距右侧安全区 12 点，保留 44 点触摸区域和屏幕高度 65% 的纵向位置；横屏避开刘海，窄尺寸下限制在安全区域内。

这些问题由代码检查和新增回归结构样例确认。当前没有连接可读取运行层级的手机，截图无法证明具体命中了哪一个原生类，因此不将本地模拟检查称作手机上已修复。发布核验见 `RELEASE-2.4.0.md`。

## 2.3.5 图片工具箱与下载整理

全屏图片按钮保留点按复制原图，长按打开“图片工具箱”：

- 复制当前显示：使用已加载位图，避免网络等待。
- 临时复制：获取原图后写入仅本机可用的剪贴板，10 分钟后由系统过期；原图获取失败时沿用当前图回退。
- 复制原图链接：粘贴图片的原始地址。
- 图片信息：查看当前已加载图片的像素大小及原图地址可用性，不把预览分辨率误报为原图规格。

## 1.6.2 全屏下载媒体解析修复

用户确认普通推文下载可以正常获取清晰度，但全屏独立入口经常提示无法读取。旧代码主要依赖分享控件的弱引用及有限的向上视图链；控件淡出、销毁或重建后，全屏入口可能失去可解析的模型。

本版改动：

- 普通和全屏下载共用 `BHRDMediaResolver`，沿相同的推文/媒体模型路径读取原生 variants。
- 普通下载按钮获得的媒体信息按真实推文标识和视频资源标识缓存五分钟，供同一视频的全屏模型使用；不缓存“任意最后一个视频”。缓存有条目上限，纯缓存读取不续期。
- 全屏优先检查当前可见播放器的实际资源地址，通过同一视频资源 ID 找回普通入口中的完整清晰度。尚未缓存的当前 MP4/HLS 地址也可交给原下载流程处理。
- 控件淡出时保留当前视频卡片的模型；换卡片时清除无匹配模型，跳过位于屏幕中心之外的邻页，避免下载上一条视频。
- 不用同一个 AVPlayer 对象的身份判断视频是否相同，每次点击重新检查 currentItem；不调用返回标量的私有方法作为对象 getter。

## 1.2.0 转推重叠修复与三种模式

旧版在 `heightForRowAtIndexPath` 中对转推返回 0，但宿主 cell 及其子视图仍参与布局，随后宿主更新或复用可能恢复可见性。这与用户截图中的内容越过行边界、叠到相邻推文上的现象一致；尚未在用户设备上捕获调用栈，不能仅凭截图断定唯一原因。

本版移除「原生转推 cell + 零行高」的处理。完全隐藏优先在时间线 JSON 和 `sections` 数据层移除转推，让宿主管理剩余行。缩略图/隐藏条则保留原始模型，原生内容子树隐藏，由独立且裁剪到行内的占位视图展示，不让推文正文沿用压缩前的布局画到邻行。

| 方式 | 展示与用途 |
| --- | --- |
| 完全隐藏 | 从数据中移除转推，不提供展开按钮；最干净，切换回其他方式后需刷新恢复被移除内容 |
| 缩略图 | 固定高度显示作者、最多四张媒体缩略图；不展示正文；点击图片或「显示这条」恢复原推文 |
| 隐藏条（默认推荐） | 固定高度的「已隐藏一条转推」及「显示这条」，不加载作者图片或媒体预览 |

在 **设置和隐私 → X 随心 → 时间线 → 转推显示方式** 中选择。

展开的转推使用 X 原有布局，不附加覆盖正文的收起按钮。可在设置中点击「重新隐藏已展开的转推」统一收起；切换显示模式也会清除临时展开状态。

完全隐藏的数据移除仅处理已识别的转推结构。未及时移除的缓存行先采用裁剪后的 1 点空白安全占位，再在主线程、列表不滚动且无未完成批量更新时移除；遇到未知 section 结构会保留安全占位，不尝试破坏私有数据。不会通过跳过增量插入来造成后续插入索引错位，也不会在布局回调内同步修改行数。

单元格复用前恢复由插件改过的可见性、选择样式和裁剪状态，并取消旧缩略图请求；下载回调检查当前 cell 的状态身份。缩略图数据不足时显示中文提示，可展开原文，不借用相邻推文的图片。

## 建议测试顺序

1. 覆盖安装 1.4.0 后完全退出并重开 X，保持默认「隐藏条」，在问题时间线快速上下来回滚动，检查行间是否仍然重叠。
2. 点击一条隐藏条的「显示这条」，检查原文和下载功能；在设置中重新隐藏展开的转推。
3. 切换「缩略图」并刷新，分别检查有图片、有视频及纯文本转推，再快速滚动确认没有串图。
4. 切换「完全隐藏」并刷新，检查连续转推和翻页；关闭隐藏或切回其他模式后再次刷新。
5. 确认普通推文和引用推文仍正常显示，以及 1.1.0 的操作栏、导航栏选项仍有效。

### 1.3.0 全屏视频测试

1. 保持默认独立下载模式，进入截图中的全屏视频，点击右下角「下载」，应先打开下载清晰度菜单；原分享按钮应继续分享。
2. 切换到另一条全屏视频后下载，确认下载的是当前视频；连续点击不应出现重复菜单。
3. 关闭独立下载按钮，启用全屏分享位置替换，再进入视频测试；关闭替换开关后确认恢复分享。
4. 检查普通时间线的分享、独立下载按钮及 1.2.0 的三种转推模式未受影响。

5. 回到首页，确认「添加＋」已隐藏，原来的推荐/关注标签仍可切换；关闭隐藏开关并重开页面可恢复。
